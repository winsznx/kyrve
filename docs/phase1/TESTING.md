# Phase 1 testing

Every claim in `GATE.md` traces to a command in this file. Where a suite cannot run in a given
environment, that is reported as SKIPPED with the exact command, never folded into a pass count.

## Commands

```bash
pnpm test:unit                      # 213, no network

```

```bash
DEPLOY_SEPOLIA=true KYRVE_CONFIRM_BROADCAST=true pnpm test:sepolia
```

## What makes a test count here

From `.claude/rules/testing.md`, applied throughout:

- **A test that cannot fail proves nothing.** Every defensive claim has a paired negative that
  fails without the defence. The import-boundary check, the deployed-bytecode check and the
  manifest validator were each run against a deliberate violation to confirm they fail.
- **Assert the *right* revert.** Contract tests assert the specific custom error, not merely that
  something reverted. This caught a live defect: the Sepolia integration passed `IMidnightAbi`
  alone to `simulateContract`, so `WrongUnits` and `QuoteNotExecutable` were undecodable — and the
  replay check only set its flag inside the `catch`, printing **ACCEPTED** for a revert it could
  not read. A false negative on the most important invariant in the suite.
- **`vm.expectRevert` binds to the next EXTERNAL call.** Two registry tests initially passed for
  the wrong reason because a helper made external calls before the call under test. Hoisted out.

## Differential testing

The quote math is not merely unit-tested; it is pinned to reality twice:

- **against the pinned Solidity** — every one of the 6,745 `tickToPrice` outputs, bit-for-bit,
  from a fixture generated by the vendored library itself;
- **against real settlement** — 36 recorded `take()` returns across two maturities, six ticks and
  three sizes. `quoteAmounts` reproduces `buyerAssets`, `sellerAssets` and the accrued continuous
  fee exactly on every row.

The second is the one that matters. The first proves the TypeScript agrees with our Solidity; only
the second proves it agrees with what the protocol actually pays.

## Determinism

`pnpm verify:generated` regenerates ABIs, the embedded deployment record, rate grids and both
Foundry fixture sets, then asserts `git diff` is empty. Three defects were found this way, each of
which would have produced a permanent meaningless diff: a repository HEAD embedded in generated
headers, a generator missing from the regeneration set, and two formatters competing over the same
files.

## Lint configuration notes

`complexity/useLiteralKeys` is **off**. Kyrve parses untrusted JSON — deployment manifests, gateway
responses, HTTP bodies — through `Record<string, unknown>`, where `source["market"]` reads as "look
up this key in a bag", which is exactly what is happening. Rewriting those to dot access would make
dynamic lookups look like known-property access.

`style/noNonNullAssertion` is an error in source and off in tests: a fixture of known shape is not
the same risk as production input.
