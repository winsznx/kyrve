# Kyrve brand lock

The authority on how the Kyrve mark may be used. The machine-readable form is
[`brand.json`](../../brand.json); the file inventory is [`ASSET-MANIFEST.md`](ASSET-MANIFEST.md);
measured evidence is [`VALIDATION.md`](VALIDATION.md).

This document is hand-authored and is the only one of the three that is. The other two are
regenerated by `pnpm brand:build` and `pnpm brand:verify` and must not be edited.

> One quote. The curve stays private.

---

## Approved masters

Four assets, approved by the owner, retained unmodified at the repository root. They are production
references, not disposable inspiration, and nothing ships that is not derived from one of them.

| Master | File | Native |
| --- | --- | --- |
| Full lockup | `kyrve-logo-source.png` | 1024x1024 RGBA |
| Symbol | `kyrve-favicon-source.png` | 1024x1024 RGBA |
| Social card | `kyrve-og-source.png` | 1731x909 RGB |
| Call to action | `kyrve-cta-source.png` | 1672x941 RGB |

SHA-256 for each is pinned in `brand.json` and re-checked on every verification run. The sources are
kept even though production exports have passed, because a derivative cannot be re-derived from a
derivative without compounding loss.

## The symbol

Layered private curves converging into one selected cobalt leaf — the quote point.

That is the product, drawn. Many confidential curves exist; exactly one becomes an executable quote;
the rest stay private. The mark is not decoration and it is not an abstract network glyph. When it
is scaled down, the element that must survive is the cobalt leaf, because the leaf is the thesis.

**The wordmark is lowercase `kyrve` in product branding.** Sentence-case `Kyrve` is correct in
prose, documentation, legal text and the start of a sentence.

## Colour

The visual system is unchanged from the approved dark palette. Kyrve is an institutional
fixed-income terminal, and the palette is doing the work that restraint does in that context.

| Token | Hex | Role | On canvas |
| --- | --- | --- | ---: |
| Onyx | `#171721` | Page canvas | — |
| Graphite | `#1e1e2a` | Card surface, one value step up, **no shadow** | 1.08:1 |
| Obsidian | `#272735` | Secondary and tertiary controls | 1.21:1 |
| Ash | `#c3c3cc` | Secondary text, labels, units | 10.16:1 |
| Ivory | `#ededf3` | Body and headings — **never `#ffffff`** | 15.25:1 |
| Cobalt | `#5266eb` | The single primary action per page | 3.78:1 |

Every ratio is recomputed by `scripts/brand/verify-assets.py` rather than transcribed.

Cobalt is the only chromatic note in the system and it is rationed: one primary action per page,
never as decoration, never as an icon fill, never on a secondary button, and never two cobalt
elements within 32px of each other. Cobalt at 3.78:1 clears WCAG AA for large text and for UI
component boundaries; it does **not** clear 4.5:1, so it is never used for body copy on canvas.

## Clear space and minimum size

**Clear space:** no element within 12% of the mark's longest edge, on any side. The shipped symbol
master already carries that padding, so placing `kyrve-symbol.png` flush against a container is
already correct. `SYMBOL_PADDING` in `scripts/brand/build-assets.py` is the same constant.

**Minimum sizes:**

| Context | Minimum |
| --- | --- |
| Symbol, screen | 24px |
| Symbol, print | 8mm |
| Full lockup, screen | 96px |

Below 24px the curve layers collapse into a single stroke and the cobalt leaf stops resolving as a
distinct element. 96px is where the descender in `kyrve` survives hinting.

## Permitted lockups

1. Symbol alone.
2. Symbol with the `kyrve` wordmark set horizontally to its right.
3. Wordmark alone, where the symbol already appears elsewhere on the same surface.

Nothing else. In particular there is no stacked lockup, no tagline lockup and no lockup with a
partner mark; if one is needed it has to be authored, not assembled.

## Favicon simplification

The favicon is the symbol alone — trimmed to its bounding box, re-padded, and centred on a square
canvas. Never the wordmark, never a letterform, never a monogram.

No separately simplified drawing is authored. At 32px and below the layered curves are permitted to
read as mass rather than as individual strokes; the cobalt leaf is the only element required to stay
individually identifiable. Legibility at those sizes comes from correct premultiplied downscaling of
the approved master, and it is verified rather than assumed — see the halo test in `VALIDATION.md`.

Required render sizes: 16, 24, 32, 48, 64, 128, 192, 512. The `.ico` carries 16, 24, 32, 48, 64, 128
and 256 as embedded PNG frames.

## Dark and light usage

### Open decision: the approved master is a light-background asset

This needs an owner decision and must not be resolved by anyone recolouring the mark.

Measured on the approved symbol master, across all 45,374 opaque pixels:

| Background | Pixels clearing 4.5:1 | Median contrast |
| --- | ---: | ---: |
| White | **100.0%** | 13.71:1 |
| Onyx `#171721` | **0.0%** | **1.30:1** |

The mark's body is deep navy, around `#142c58`. Against Onyx that is 1.30:1 — for practical purposes
invisible. The full lockup is worse, at 1.20:1 median with 0.1% of pixels clearing even 3:1.

The dark presentation of the brand does exist, but only *baked into* the approved OG and CTA
rasters, and there it sits on a near-black field (`#01091a` and `#00060f` respectively) rather than
on Onyx. That is a different background from the product canvas.

So there is no approved asset for the case the application actually needs most: the symbol placed on
the Onyx canvas, in the header. Three ways out, none of which I will take unilaterally:

1. **Commission a dark-canvas master** from the original design source, keeping the same geometry
   with values lifted for the Onyx field. Cleanest, and the only option that yields a true approved
   asset.
2. **Place the header mark on a near-black plate** matching the OG field, accepting a visible
   rectangle in the header.
3. **Use the wordmark alone in the header**, in Ivory, and reserve the symbol for light surfaces,
   social cards and the favicon.

Until that decision is made, the application header wiring in this repository points at the approved
symbol without recolouring it, and `scripts/brand/verify-assets.py` fails if the mark ever starts
clearing 4.5:1 on Onyx — because the only way that happens is a recolour, which is forbidden.

### Monochrome

One-colour reproduction uses the mark's **silhouette in a single ink**, never a flattened greyscale
of the gradient. On light: `#132748`. On dark: Ivory `#ededf3`.

## Forbidden modifications

- Recolouring the mark — **including** to make it legible on Onyx.
- Regenerating, redrawing or auto-tracing the mark.
- Rotating, skewing, mirroring, or scaling non-uniformly.
- Applying shadow, glow, outline, stroke or bevel. The system has no shadows anywhere.
- Placing the mark on a photographic or patterned background.
- Reconstructing the wordmark in a substitute typeface.
- Cropping the symbol, or altering the trim padding.
- Using the symbol as a repeating pattern or watermark.
- Upscaling any export beyond its approved source resolution.

## No SVG, and why that is stated rather than worked around

There is no SVG master and none is claimed.

The approved artwork carries soft radial glow and gradient fills whose geometry cannot be faithfully
reconstructed as editable vector paths. Auto-tracing the raster edge and shipping the result as a
production SVG would be a false claim about what the file is — it would look approximately right at
one size, carry thousands of meaningless nodes, and be impossible for a designer to edit. If a true
vector master is required it has to come from the original design source.

## Honesty

The same rule that governs Kyrve's protocol claims governs its brand assets: nothing asserted without
executable evidence. Every hash, dimension, byte count and contrast ratio in `brand.json`,
`ASSET-MANIFEST.md` and `VALIDATION.md` is recomputed from the files on disk by
`scripts/brand/verify-assets.py`, and the build fails if any of them stops being true.
