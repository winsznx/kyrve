## P-1 · `OPERATION-BUDGET.md` §5 — the capacity table omits two per-epoch costs · CORRECTION

*Executable proof: `packages/config/test/budget.test.ts`, 20 tests.*

The capacity table published in `docs/day0/OPERATION-BUDGET.md` §5 (and reproduced in PRD v1.1
A-10) is generated by the model

```
cells × accumulateCell
  + providers × (cacheProvider + allocate)
  + leaves    × (finalizeLeaf + reduceWinnerLeaf)
```

which reproduces every published row **to the exact wei** — that is how the model was identified.
It omits two costs that are genuinely incurred once per epoch:

| Omitted | Cost |
|---|---|
| Stage C per-chunk fixed overhead | 166,954 gas × chunk count |
| Stage E2 `publishWinner` | 90,076 gas |

Per-epoch gas is therefore understated:

| Providers × leaves | Published | Complete | Understated by |
|---|---:|---:|---:|
| 4 × 16 | 10,637,568 | 10,894,598 | 257,030 (2.42%) |
| 8 × 32 | 31,054,592 | 31,311,622 | 257,030 (0.83%) |
| 8 × 64 | 58,725,376 | 59,149,360 | 423,984 (0.72%) |
| 16 × 64 | 101,227,008 | 101,984,900 | 757,892 (0.75%) |
| **16 × 128** | **195,686,400** | **197,112,108** | **1,425,708 (0.73%)** |

Excluding Stage A `seedProvider` is **correct** and is not part of this finding: a provider mandate
is sealed once and reused across every subsequent epoch, so it is not an epoch cost. It remains
exported separately for mandate-submission sizing.

**The Day 0 conclusion is unaffected.** The full 16 × 128 universe still executes well inside the
gas ceiling and the 15-minute Workflow window.

**Applied as:** `packages/config/src/budget.ts` exports both models. `publishedEpochGas()`
reproduces the Day 0 table exactly so the evidence stays checkable against this repository;
`planEpoch()` is the corrected, stage-aware schedule that production code uses. `planEpoch` also
returns a real transaction plan rather than dividing total gas by the ceiling, because stages
cannot be merged across a transaction boundary.

## P-2 · §11.9 / v1.1 A-8 — the justification for rounding down is wrong · CORRECTION

*Executable proof: `contracts/integration/test/QuoteMathDifferential.t.sol ::
test_roundingDirection_neitherOverdraws_butUpInflatesBorrowerDebt`, plus 400,000 sampled
(price, target) pairs.*

Day 0 finding D-15, applied as PRD v1.1 A-8, justifies deriving `units` by rounding down with:

> "Rounding up can overdraw and would break §19.2."

**That justification is false.** The Day 0 test named `test_roundingUp_canOverdrawTheReservation`
never actually asserted it — it only checked the round-down case, so the claim in its own name went
unverified.

Because tick prices are capped at par (`tickToPrice(tick) ≤ WAD` for every tick), for all `t` and
all `p ∈ (0, WAD]`:

```
unitsUp = ceil(t·W/p)  <  t·W/p + 1
owedUp  = floor(unitsUp·p/W)  <  t + p/W  ≤  t + 1
⇒ owedUp ≤ t
```

Rounding up therefore **cannot** overdraw either. Confirmed empirically: zero witnesses across
400,000 sampled `(price, target)` pairs, and zero across the accessible tick grid in the contract
test.

**Rounding down remains normative**, for the real reason:

Rounding up inflates `units`, so the borrower carries face value whose exact price exceeds the
assets providers reserved, and Midnight's own flooring silently hands that fraction to the maker.
Rounding down instead leaves an explicit residue — bounded at 2 wei, re-measured here — that routes
to the §19.8 dust account. The choice is about **where the rounding residue goes and who is told
about it**, not about solvency.

**Applied as:** the contract test now asserts what is true (neither direction overdraws; round-up
demonstrably inflates units; round-down dust stays ≤ 2 wei), and
`packages/quote-math/src/quote.ts` documents the corrected rationale at the point of use.

## P-3 · §31 — `verify:live` needs the EIP-1967 boundary stated · GAP

*Source proof: Solidity has no cross-contract storage read.*

PRD v1.1 A-18 requires `verify:live` to check the deployment is the expected one. An early draft of
`KyrveDeploymentVerifier` tried to read the NoxCompute proxy's EIP-1967 implementation slot from
Solidity and silently returned the proxy's own address, which would have compared the wrong
bytecode and reported a **pass**.

A contract cannot read another contract's storage. The proxy-to-implementation binding is therefore
not verifiable on chain and must be established off chain.

**Applied as:** `KyrveProtocolRegistry.Deployment` pins the implementation **address** (whose code
hash *is* checkable on chain) alongside its hash, `KyrveDeploymentVerifier` documents precisely
what it does and does not prove, and `scripts/verify/deployment.ts` reads the EIP-1967 slot with
`eth_getStorageAt` to close the gap.

## P-4 · §21 — Workers Paid is a deployment prerequisite, not a runtime detail · CONFIRMED

No change. Recorded because it is easy to lose: the Cloudflare Free plan allows 50 subrequests per
invocation **counting D1 and R2 calls**, which cannot cover one block of indexing (A-13). This is a
billing prerequisite that must be satisfied before the indexer can run at all, not a limit that
degrades gracefully.
